# Memory Hole Lab

メモリーホール内の粒子輸送と表面帯電を調べるWindowsローカルアプリです。仕様書v0.5の固定形状Aを段階的に実装した開発版です。日本語React画面、FastAPI制御、独立した計算ワーカーを備えています。

## 起動

このPCでは依存関係と画面ビルドを準備済みです。`start.cmd`を実行すると、ローカルサーバーとブラウザを開きます。

```powershell
.\launch.ps1
```

画面は http://127.0.0.1:8765 です。CPU環境のみ準備する場合は`.\launch.ps1 -Cpu`を使い、画面の計算デバイスもCPUへ切り替えてください。画面ソースを変更した後は`-Build`を付けて再ビルドします。既に起動中の場合は同じ画面を開きます。

手動セットアップにはPython 3.12～3.13、uv、Node.js/npmが必要です。

```powershell
uv sync --extra gpu
Set-Location frontend
npm.cmd ci
npm.cmd run build
Set-Location ..
uv run --extra gpu python -m memory_hole
```

GPUグループはCuPyとCUDA 13のコンポーネントをプロジェクトの仮想環境に導入します。対応NVIDIAドライバが必要です。CPU専用の環境は`uv sync`で準備できます。

### status.jsonへのアクセスが拒否される場合

Windowsでは、ファイルを開いている処理が削除共有を許可していないと、読込み中のファイルの置換が拒否されます（[Microsoftのファイル共有仕様](https://learn.microsoft.com/ja-jp/windows/win32/api/fileapi/nf-fileapi-createfilew)）。状態・プレビューJSONは書込みごとに異なる一時ファイルを使い、置換時のアクセス拒否を最大2秒再試行します。結果・チェックポイントHDF5の置換にも同じ再試行を適用します。状態読込みは最大0.15秒再試行し、それでも読めない場合は画面に「状態を確認できません」と原因・保存先を表示します。この状態のジョブを自動的に再実行せず、ほかの待機ジョブの処理を続けます。ワーカーの失敗状態を書けない場合も、元のエラーをジョブの`error.log`へ保存し、その保存もできなければ`server.error.log`へ記録します。

再試行で解消しない場合は、表示されたファイルと保存先の書込権限・他のアプリによる使用を確認してください。Dドライブ直下へのクローンでも、フォルダーを作成できることと既存ファイルを置換できることは別の権限です。ユーザー用の保存先を使う場合は、実行中の計算を停止してサーバーを終了した後、次のように起動します。

```powershell
.\launch.ps1 -DataDir "$env:LOCALAPPDATA\MemoryHoleLab"
# CPU専用環境では -Cpu も指定
```

`start.cmd -DataDir <保存先>`や環境変数`MEMORY_HOLE_DATA`でも指定できます。ジョブ・取込分布・初期設定とサーバーログ・PIDを同じ保存先に置き、起動前に作成・読込み・置換を検査します。既定の保存先はリポジトリ内の`data`です。既存データは自動移動されないため、保存先を変えると以前のジョブや取込分布は表示されません。以前のデータを使う場合はサーバー終了後に`data`の内容を指定先へコピーするか、元の保存先で起動してください。すでに別の保存先でサーバーが起動中の場合は、終了・再起動が必要だと案内します。

この修正ではWindowsの実ファイルロックを再現し、解除後の置換成功、同時JSON更新、永続的なアクセス拒否で旧状態を保持すること、スケジューラの継続・復旧、元のエラーログ保存を確認しました。既存の数値計算を含むPythonテスト41件が通過しています。実サーバーでも更新中に21回ロックしながら計算完了、読込み拒否時の状態表示と解除後の復帰、空白を含む保存先への起動・ログ保存を確認しました。記録は`data/qa/storage_api_check.json`です。会社PC固有の権限設定やセキュリティ製品による制限は直接検証していません。

## 最初の操作

1. 設定画面でChannel径、膜厚、dummy個数・径・間隔を編集します。金属をクリックすると、そのdummyの距離を個別に変更できます。中心距離、xy座標による配置にも対応します。
2. 形状検査が通ったら、帯電なし・指定電荷・自己無撞着帯電を選びます。接触・重複・未接続・領域外の形状は実行できません。
3. 入口のイオン種と電子流束、波形、数値条件を設定します。全設定JSONから半径プロファイル、漏れ時間、反射・中性化・二次電子係数、乱数シードも編集できます。
4. 計算を開始し、場と軌道、表面電荷、衝突統計を確認します。帯電更新ごとに表示時刻を選択できます。
5. 完了ジョブを比較画面で選ぶと、底部到達率と条件付き95%区間、平均エネルギー、底部重心を比較できます。

寸法掃引は値リストを指定します。たとえば`geometry.gap_nm`に`50,100,150`を入力します。APIでは最大3寸法の直積を64ケースまで実行できます。特定dummyの掃引は、個別設定を作成してから`geometry.dummies.0.gap_nm`などを指定します。

各ジョブは開始時の設定を固定します。実行中の編集は別ジョブに適用します。停止時は完了済みの帯電更新と乱数状態を保存し、途中の更新は同じ乱数から再計算します。形状・条件・コード版の異なるチェックポイントは再開できません。

## 飽和帯電まで計算

設定画面の「計算モード」で**飽和帯電まで**を選ぶと、自己無撞着帯電を継続し、指定した許容差内で安定した時点で自動終了します。時間指定の自己無撞着モードも利用できます。JSONでは`mode: "self_consistent"`と`numerics.run_until: "saturation"`を指定します。判定条件は`numerics.saturation`です。旧設定は`run_until: "time"`として読み込みます。

| 条件 | 既定値 |
| --- | --- |
| 判定する物理時間幅 | 10 µs |
| 判定窓内の帯電更新数（目安） | 4回 |
| 電位変化の許容値 | 0.1 V |
| 表面電荷密度の許容値 | 絶対1×10⁻⁷ C/m²＋相対1% |
| 観測窓数・連続安定窓数 | 3窓目から数え、5窓連続で成立 |
| 未解決の絶対電荷 / 入射絶対電荷 | 1%以下 |
| 最大物理時間・最大帯電更新回数 | 1000 µs・10000回 |

各時間窓の開始時を基準に、窓内で観測した**全FEM節点の最大電位変化**と**表面パッチ面積で重み付けした絶対電荷密度変化の平均**を調べます。電荷密度の許容値は「絶対許容値＋相対許容値×窓内の最大面積平均絶対電荷密度」です。両方の変化と未解決電荷の割合が条件を満たした窓が連続した場合に、飽和判定が成立します。正負の電荷が相殺した合計値だけで判定せず、窓の終わりに元へ戻る振動も窓内の最大変化で検出します。時間刻みを短縮しても、完全な物理時間窓を経過するまでは安定回数を増やしません。各窓の境界で時間刻みを区切り、途中の窓は上限時に飽和成立へ数えません。

実行画面には物理時間と連続安定窓数、結果には保存時刻ごとの電位・電荷変化と判定値を表示します。終了理由は**飽和判定成立（指定許容差内）**、**最大時間で終了（未飽和）**、**最大更新回数で終了（未飽和）**を区別してJSONとHDF5へ保存します。上限使用率は飽和への進み具合を表す値ではありません。チェックポイントは判定窓の基準電荷、窓内の最大変化、連続判定回数も保存し、停止・再開で引き継ぎます。終了時は保存間隔によらず最終時刻を保存します。長い計算の保存間隔は全設定JSONの`numerics.save_every_steps`で変更できます。

これは現在の凍結RF・平均場モデル内での**数値的な飽和判定**で、実デバイスの飽和電位や統計的な信頼区間を保証する条件ではありません。粒子サンプリングの揺らぎが大きい場合は、サンプル数・判定時間幅・許容差を見直してください。既定値は工程条件に対する推奨値ではありません。

誤判定（微小な時間刻み、局所電荷の相殺、窓内の振動、未解決粒子）、漏れの指数減衰、窓の途中での停止・再開、両上限での終了を含め、回帰テスト26件が通過しています。ローカルアプリでは`uv run --extra gpu python scripts/check_saturation_api.py`で3種類の終了ケースを作成でき、`node scripts/check_saturation_ui.cjs`で画面表示を確認できます（PlaywrightとEdgeが必要）。確認結果は`data/qa/saturation_api_check.json`と`data/qa/saturation_ui_check.json`です。漏れ減衰の検証ジョブは、入射流束をゼロにした解析解確認用のケースであり、提供IAEDFケースの飽和を示す結果ではありません。

## 電場・粒子のアニメーション

「場と軌道」で結果ジョブを選び、再生モードを切り替えます。確認用の「アニメーション検証 · 時刻付きイオン・電子 · GPU」ジョブを準備しています。

- **帯電の時間変化**：保存済みの帯電状態を順に表示します。電位・電場・表面電荷の表示を切り替えられ、電場はRF位相0°です。1×は1保存時刻/秒です。保存時刻が1点の場合は再生できません。
- **粒子の飛行**：新しい計算では各保存時刻の代表飛行区間を、保存した経過時刻に沿ってns単位で再生します。イオンは橙、電子は緑です。軌道のRF位相を選ぶと、その軌道を計算した更新前の凍結電場と表面電荷を表示します。計算場の帯電時刻は操作欄に表示します。
- **再生操作**：再生・一時停止、先頭へ戻る、スライダー、0.25～4×の速度、繰り返しに対応します。粒子は1×で全表示時間を約6秒に引き伸ばします。再生中も3Dカメラを回転・拡大でき、時刻や表示レイヤーを変えても視点を保持します。

古い計算には軌道点の経過時刻がありません。この場合は経路上の位置を0～100%で再生し、「実時間ではありません」と表示します。既存ファイルへ時刻を推測して追記しません。代表軌道がないジョブは粒子再生を無効にします。

表示粒子を増やすには、設定画面の「実行条件」→「アニメーション用の代表軌道数」を変更して再計算します。既定は12本、上限は1000本、0本では軌道を保存しません。例えば1000本なら、イオン1種と電子へ各500本を配分します。これは保存する飛行区間数の上限で、未追跡の粒子などにより保存数が少なくなる場合があります。粒子再生では選択したRF位相の軌道だけを表示するため、画面の表示数は保存合計より少なくなる場合があります。全設定JSONでは`numerics.representative_trajectories`が同じ設定です。「サンプル数 / 種 / 更新」は計算統計用であり、表示数の指定には使いません。保存軌道を増やすとJSON・HDF5・チェックポイントの容量も増えます。粒子マーカーはThree.jsの`InstancedMesh`で一括描画します。

全粒子を表示する機能ではありません。新しい計算は指定した代表軌道数を種ごとに配分し、帯電更新ごとに選び直します。代表飛行区間は表示上の共通の飛行時刻で再生し、保存点間の位置を補間します。粒子の実際の入射頻度や表示数から到達率を読み取りません。RF位相は飛行中固定で、RF時間依存ソルバーを追加したものではありません。色の範囲は各表示状態で自動調整し、凡例に実数値と単位を表示します。

時刻付き軌道と対応する電場・表面電荷はJSONおよびHDF5へ保存します。HDF5の`trajectory_times/`は秒、`trajectory_fields/`は表示用に間引いた場で、`time_series/`にも保存時刻ごとの軌道と対応場を含めます。チェックポイントの保存・再開とCPU/GPUの軌道時刻一致を回帰テストで確認しました。ブラウザで再生・停止・シーク・速度・終了・視点保持・旧データ・空軌道・読込中のジョブ切替・スマートフォン表示を確認し、結果は`data/qa/animation_check.json`と`data/qa/animation_ui_check.json`に保存しています。

1000本対応では、単一RF位相の表示負荷検証ジョブ「アニメーション検証 · 1000本 · GPU」でイオン500本・電子500本の同時再生を確認しました。このPCのEdgeでの短時間測定は、デスクトップ・モバイル幅とも約60 fpsでした。1000本×128点の軌道・時刻をチェックポイントとHDF5へ保存する回帰テストを含め、Pythonテスト16件が通過しています。ブラウザ検証は`node scripts/check_large_animation_ui.cjs <単一位相の1000本ジョブID>`で実行できます（PlaywrightとEdgeが必要）。測定記録は`data/qa/animation_1000_ui_check.json`です。実測ケースの容量はJSON約3.2 MB、チェックポイント約1.1 MB、結果HDF5約8.6 MBで、軌道の長さと保存時刻数によって変わります。

## 2D断面プロット

**断面2D**タブで結果ジョブを選び、断面の向き・位置・表示量を指定します。保存済みの完全なFEMメッシュを読み込むため、以前のHDF5結果も再計算せず表示できます。完了した帯電更新にHDF5が保存されていれば、計算中や停止中のジョブでも使えます。

- **XZ**はy位置、**YZ**はx位置、**XY**は深さzをnm単位で指定します。z=0はCarbon上面、zは下向きに増加します。XYではyが上向きに増加します。
- **縦断面・角度指定**は、x軸からの角度θで水平軸sを決めます。s方向は`(cosθ, sinθ, 0)`、断面位置nの方向は`(-sinθ, cosθ, 0)`です。n=0はホール中心を通ります。
- 表示量は**電位、電場の大きさ、Ex・Ey・Ez、表面電荷密度**です。表示時刻で保存済みの帯電更新を選びます。使う場は各更新の**RF位相0°**の保存値で、粒子アニメーションで選んだRF位相とは独立です。
- 材料境界、気相のみ、等電位線、断面内の電場方向を切り替えられます。色範囲の上下限を指定すると、時刻を切り替えても同じ範囲を保持します。矢印の長さは規格化し、方向を示します。断面に垂直な成分はEx・Ey・Ezで確認します。
- **＋／−**で拡大・縮小し、拡大後はドラッグで移動します。ポインター位置では最寄りの表示格子点の座標・値、または壁面パッチの電荷密度を読み取れます。**PNG保存**は現在の範囲を軸・時刻・色凡例付きで保存し、**断面CSV**は断面全体の格子値をSI単位（座標はnm）で保存します。表面電荷を選んだCSVは交線または断面と一致する面のパッチ座標・密度を保存します。

四面体と断面の交差多角形を作り、その内部だけに格子点を置きます。電位はP1節点値の線形補間、電場は交差した要素内の保存値です。導体など、FEM要素がない領域を補間で埋めず、格子値を空欄・灰色にします。「気相のみ」で非表示になったSiO₂も灰色です。界面上の同じ点を複数材料が含む場合は気相側を優先します。表面電荷密度は壁面と断面の交線に着色し、帯電面が断面と一致するときだけ面を着色します。体積電荷密度へ読み替えません。

表示格子は長辺121・241・401点から選び、物理座標の縦横比を保ちます。格子を増やしても元のFEM解の精度は変わりません。等電位線は表示格子から求めるため、細い構造の確認には詳細格子とFEMメッシュの収束確認を使ってください。

APIは`GET /api/jobs/<ID>/slice?plane=xz&position_nm=0&resolution=241&step=1`です。`plane`は`xy/xz/yz/vertical`、縦断面の角度は`angle_deg`です。`step`省略時は最新のHDF5結果を使います。完全なメッシュ、各時刻の電位・電場・表面電荷が必要で、表示用の間引きJSONだけから断面は作りません。

解析的な線形電位、電場成分、材料界面で不連続な電場、共有面を通る断面、領域外マスク、帯電面の交線・一致面、過去時刻のHDF5読込み、API入力検査を追加しました。既存機能を含むPythonテスト57件が通過しています。実データの4方向・保存時刻・詳細格子は`data/qa/section_api_check.json`です。ブラウザで時刻・表示量・色範囲・拡大移動・値の読取り・PNG/CSV出力・旧ジョブ・読込み中のジョブ切替・モバイル幅を確認し、記録は`data/qa/section_ui_check.json`に保存しています。ブラウザ検証は`node scripts/check_section_ui.cjs`です。PlaywrightとEdgeに加え、このPCで作成したスクリプト内のジョブIDに対応する保存結果が必要です。

## 提供されたIAEDFデータ

`sample-20mTorr.npz`と`sample-20mTorr.json`は変更していません。両ファイル内部の圧力は**10 mTorr**であり、ファイル名とは異なります。内部値を採用した検証ケースを初期設定にしています。

- p0の30万粒子から299,566到達粒子を選択。エネルギー・投影角・到達RF位相を同じ粒子インデックスで保持します。
- 指定ウェハ波形は`−170 + 158 sin(位相) V`、周波数13.56 MHzです。NPZの`V_e`とJSONの正弦波設定を照合します。
- 速度3成分は未保存です。面外速度をゼロとする近似で読み込みます。この近似は3D極角分布の再現ではありません。
- イオン絶対流束は密度×Bohm速度×到達割合による**推定**です。規格化IAEDFを絶対流束へ読み替えていません。上流の粒子重み・コレクタ面積との照合は未完了です。
- 電子は同じ温度・密度・`V_p`・`V_e`を使い、位相ごとのBoltzmann減衰と法線速度で重み付けした熱分布から生成します。実測電子分布ではありません。
- 評価面はCarbon上面z=0です。入口面のFEM電位をウェハ波形に拘束し、既に含まれるシース加速を追加しません。入口上方のフリンジ輸送の評価には、対応する上流コレクタのデータが必要です。

取込済みデータは`data/distributions/`、初期設定は`data/preset.json`、条件例は`examples/sample_10mtorr_case.json`にあります。例の分布IDはこのローカル環境の取込データを参照します。別環境ではペアを再取込してください。再生成は`uv run --extra gpu python scripts/import_sample.py`です。

画面からNPZと上流config.jsonを一緒に渡すと、1D正弦波ケースの波形・質量・温度・流束推定を更新します。分布だけを渡す場合は、現在の評価面・波形を記録します。旧NPZの投影角は、面外速度ゼロ近似を明示した場合だけ取り込めます。2D入力はコレクタのx範囲を必須とします。

## CSV入力契約

UTF-8 CSVの以下の形式に対応します。内部の法線は+z、xとyは接線です。

```csv
energy_ev,theta_deg,phi_deg,phase_deg,weight
100,2,30,90,1
120,4,60,180,2
```

`theta_deg`は法線からの3D極角、`phi_deg`は接線面内の方位です。速度を直接入力する場合は`vx_m_s,vy_m_s,vz_m_s`を使い、`vz_m_s`を正にします。`phase_deg`と`weight`は任意です。

相関ビン形式は`energy_low_ev,energy_high_ev,theta_low_deg,theta_high_deg,probability`です。確率を正規化してビンを選び、ビン内のエネルギー・角度は一様、方位は一様として生成します。密度CSVを自動的に確率と解釈しません。

## 数値モデルと保存

Gmshの境界適合四面体と一次FEMで、気相とSiO₂をまとめて倍精度で解きます。誘電率は材料ごとに設定し、露出SiO₂界面の電荷を弱形式の表面項へ一度だけ加えます。Carbon・埋め込み金属・基板の内部は未知量から除外し、共通の指定電位を与えます。dummyに粒子開口を設けません。4900 pFは全ウェハの記録用容量で、局所電流からウェハ電位を求める計算には使いません。

固定形状のFEM行列と電位基底を再利用します。大きなメッシュではAMG前処理を使用します。CPU輸送はNumba、GPU輸送はCuPy RawKernelです。P1四面体内の一定電場で放物線軌道と各面の最初の交差を解き、材料界面で再積分します。最大ステップ・相互作用回数に達した粒子は未解決として残し、吸収には数えません。

代表粒子重みは絶対流束×注入面積×物理時間÷サンプル数です。粒子飛行時間刻みと帯電更新時間刻みを分けます。自己無撞着モードでは電位変化上限に応じて物理時間を短縮し、代表粒子重みも同じ比率で変更します。数値緩和係数を物理時間へ読み替えません。

`data/jobs/<ID>/`に次を保存します。

| ファイル | 内容 |
| --- | --- |
| config.json | 版付き入力設定 |
| status.json | ワーカーの進捗・状態 |
| results.h5 | SIメッシュ、場、表面電荷、衝突分布、保存時刻の場、代表軌道、メタ情報 |
| checkpoint.h5 | 表面電荷、累積統計、時間、乱数状態、形状・メッシュ・コードのハッシュ |
| preview.json | 画面向けの間引いた場と統計 |
| snapshots/ | 保存時刻ごとのHDF5と表示データ |

画面のCSV出力は表面パッチの座標・面積・電荷密度・種別衝突重みです。衝突エネルギー・角度の同時ヒストグラムと深さ・方位分布はHDF5へ保存します。場の表示はRF位相0°の節点値・気相ベクトルで、全軌道の保存は行いません。

独立シード区間はケース全体の出力からStudent t（自由度4）で計算しました。帯電刻みの比較は同じ5シードを対応させ、差の区間と基準値の比を評価しています。到達率とエネルギーは計算時間全体の集計で、最終時刻の瞬間値ではありません。電子の希少イベントに対する精度保証はできていません。20ケースの最大電荷保存残差は6.84×10⁻¹⁶、5000回の対照計算は7.16×10⁻¹⁶でした。
